## Done in this commit

1. **Analyze page, the role field.** "Target role" was a fixed list of five generic titles. It is now
   "Role you are hiring for" and lists only the roles the account saved in Role review (plus "Not for a saved role").
   Choosing one uses that role's saved brief for evidence matching and hides the free-text job description.
   The five-title field is kept as what it really is, "CV-stated role", read from the CV and correctable.
   Files: `src/app/analyze/page.tsx`, `src/components/analyze-candidate-workflow.tsx`.
2. **Analyze page, profile links.** A CV with only a GitHub profile link used to end in "paste the repository URLs".
   "List public projects" now lists the person's own public projects (no forks, no empty ones, twelve at most,
   most recently updated first) for the recruiter to pick from. A profile link typed into the repository field does the
   same instead of an error. Origin is recorded as `GitHub profile`, a value the schema already had.
   Files: `src/services/github/profile.ts` (+ tests), `src/app/api/github/profile/route.ts`.
   It asks GitHub's public interface first and reads the profile page if that is refused; both are free and need no
   token. If both fail the page says to paste links, as before. Setting the optional `GITHUB_TOKEN` in Vercel raises
   GitHub's hourly limit from 60 to 5,000 and makes the first source reliable on shared hosting.
3. **Limits typed by hand.** "96 MB" and "5,000" on the Analyze page now come from `ARCHIVE_LIMITS` and `FILE_LIMITS`.
4. **Source channel.** Every applicant is saved with the source `"CodeProof"` (`src/features/candidates/store.ts`,
   two inserts), and nothing lets a recruiter change it. Hiring Insights therefore compared one channel with four
   empty ones and could announce "CodeProof is your strongest channel". The table and that sentence now appear only
   when at least two channels hold applicants (`hasSourceComparison`, `deriveInsights`).
5. **Unused sample dataset.** `src/features/hiring-analytics/mock/mockHiringData.ts` generated 88 synthetic candidates
   and was imported by nothing. Removed.

## Found and not changed (the remaining work)

1. **The five fixed candidate roles** (`ROLES` in `src/features/hiring-analytics/types.ts`). Still the only choices for
   an applicant's own role in `CandidateCvIntakeForm`, `CandidateBatchIntakeForm`, `InterviewDesk` (add candidate
   without repository) and the Analyze page, and enforced by `z.enum(ROLES)` in `api/candidates/analyze`,
   `api/candidates/intake-cv` and `api/candidates`. `suggestedRole()` in `resume-matching/discovery.ts` falls back to
   "Frontend Engineer" when nothing matches, so a mobile or QA engineer's record is labelled wrongly, and a CV that
   mentions Kubernetes is called "DevOps Engineer". The `role` column is plain text in SQLite and PostgreSQL, so no
   migration is needed. Suggested change: keep the five as suggestions, add "Other" with a text field, store the CV's
   own headline (`statedRoleOf`) when it has one, and stop guessing a default.
2. **Source channel is still not recordable.** Item 4 above only hides the misleading output. To make it real: a
   source field at intake and on the applicant's status card, validated against `SOURCE_CHANNELS`, with a neutral
   value for "not recorded".
3. **The demo flag.** No screen creates demo records any more, but `api/candidates/analyze` still accepts
   `isDemo=true` from the form and the labelled demo paths remain for older records (home, Hiring Insights, review
   queue, role review). Decide whether to refuse the flag from clients.
4. **`/api/analyze`.** An older streaming endpoint that no screen or test calls. It is behind sign-in. Remove or keep.
5. **Two kinds of "requirements".** `/requirements` (Company requirements) is still used as the fallback job brief
   when the Analyze page sends none. With saved roles in place this is a second, older input for the same idea.
6. **A browser test for the new Analyze page.** Add to `tests/browser/analyze-intake.spec.ts`: a saved role appears in
   the list and its brief is sent; a profile link lists projects (fulfil `**/api/github/profile` with a canned answer
   so the test needs no network).
7. **Not audited:** the Compare page, the review queue, the owner console and the interview workspace were only
   searched for fixed data, not walked screen by screen.
